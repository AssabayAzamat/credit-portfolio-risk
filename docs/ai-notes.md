# Работа с ИИ и исправления

Проект реализован с агентом Codex. Аналог CLAUDE.md — AGENTS.md в корне.
Агент написал SQL, YAML, загрузчик, Vega-Lite спеки, HTML и независимую сверку,
затем запускал проверки на настоящем PostgreSQL 16.14.
Входные CSV рассматривались как данные, не как инструкции.

Фактически обнаруженные ошибки агента:

1. **Общие цветовые шкалы в Vega-Lite.** Первая версия hconcat-графика динамики не разделяла шкалы объёмов и долей. Компилятор предупредил о конфликте domain/range, что могло присвоить неверные цвета сериям. Добавлено `resolve.scale.color: independent`; повторная компиляция прошла без предупреждений.
2. **Копирование библиотек для автономного HTML.** Первая версия vendor.mjs обращалась к package.json через exports пакета vega-embed, где этот путь закрыт. Следующая попытка приняла служебную папку build за корень vega-lite. Исправлено: путь ищется вверх от публичного entry point до существующего build/<bundle>. Фактический браузерный просмотр подтвердил загрузку всех трёх библиотек.
3. **Предположение о запуске фонового PostgreSQL.** После pg_ctl start процесс не был доступен из следующего изолированного shell-вызова. Для проверки сервер запущен дочерним процессом в удерживаемой сессии; загрузчик, тесты и Decimal-сверка реально подключились к PostgreSQL 16.14. Этот временный сервер не является зависимостью репозитория; воспроизводимый способ запуска — Compose.

При анализе обнаружено по 30 точных дублей на дату. Они удаляются в reporting,
исходные строки сохраняются в raw. Это свойство данных, а не ошибка ИИ.

Границы PAR и приоритет NPL были заданы до реализации и подтверждены тестами.
YAML содержит аддитивные числители, а доли — SQL-отношения сумм: усреднять доли кредитов нельзя.
Проверка состоит из двух независимых реализаций: PostgreSQL NUMERIC и Python Decimal,
а не из сравнения результата одной формулы с её копией.
